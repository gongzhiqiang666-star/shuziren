# 本地运营工作台前端

Vue 3 + TypeScript + Vite。业务接口遵循 `../docs/MVP_CONTRACT.md`，不包含演示数据、伪造媒体或自动付费回退。

## 开发与构建

使用 Node.js 24，在本目录运行：

```sh
npm ci
npm run dev
```

开发服务器仅监听 `127.0.0.1`；`/api` 与 `/healthz` 默认代理至 `http://127.0.0.1:8080`。可以通过启动 Vite 时的 `API_PROXY_TARGET` 环境变量更改本地代理目标。

```sh
npm run typecheck
npm test
npm run build
```

构建产物位于 `web/dist`，由 Go 服务的 `WEB_DIST` 指向该目录并同源提供。无需外部字体、付费 UI 服务或第三方图标网络请求。

## 已接入的流程

- 工作台口令认证；口令只在页面内存中，刷新、退出后重新登录。
- 创建与切换店铺；商品金额精确保存为整数分，编辑带版本号。
- 品牌人格、FAQ、人工记忆和质量档案编辑。
- 本地场次创建、暂停接管、恢复与本地结束。
- 人工话术或 DeepSeek 草稿、人工核对与审批、本地语音排队、试听、媒体派发、取消及持久任务查看。
- LiveTalking 音视频由浏览器 `RTCPeerConnection` 以 `recvonly` 接收，协商通过受认证同源后端；不采集摄像头或麦克风。
- 音频使用带 Bearer 的 `fetch` 读取后创建临时 Blob URL，关闭预览时撤销 URL，不把口令放进链接。

页面将服务“已配置”与媒体“已连接”分别显示。`sent` 只显示“上游已接收”，不证明观众已听到；`delivery_unknown` 不提供重新发送按钮。商品、人设版本与执行批次过时，会在前端禁用继续审批和派发，后端仍是最终执行校验方。

本版媒体预览依赖工作台页面。离开工作台或断开预览会关闭 Peer，只有当前场次真正进入 WebRTC connected 状态后才允许派发；数据库中保留的媒体会话 ID 不代表连接仍然有效。独立 OBS 媒体来源尚未实现。

质量核验是人工记录，默认全未通过；未保存的默认档案不会显示为实测通过。当前检索明确标识为关键词检索，淘宝评论和正式直播接入不冒充已经完成。

## 测试边界

单元与组件测试使用隔离的接口和 WebRTC mock，覆盖精确金额、版本/批次失效、派发结果不明、错误表单保留、口令存储、认证音频读取和 WebRTC 协商状态。它们不证明本地模型、GPU、真实 LiveTalking 或淘宝直播已经通过验收。实际媒体和平台验证仍按项目验收文档执行。

# V04-04 / X01 验收方法 V04-Q1.2

本协议与`scripts/fixtures/v04-quality-corpus.json`在50条批测前固定。此前单片探索记录独立保留，不充当50条通过。语料是本机合成测试文本，不是商家事实或待发布话术。

## 输入与执行

- Q001～010数字/日期/单位，Q011～020品牌，Q021～030中英混读，Q031～040停顿/语气，Q041～046同句不同语速，Q047长段，Q048～050末尾/否定词。
- 固定本机RTX3060、同一授权参考音、同一750帧720×1280形象。逐条新文本禁用TTS缓存；同一条WAV原样分别驱动CUDA基线与TRT FP16，每片重置到同一素材起始帧。
- 每个后端进程内复用模型，初始化、首片冷态和后续热态分别记录。语音先生成后关闭工作进程，再分别运行两个图像后端，避免把其他模型显存误计为本后端；整机其他应用占用另列。
- CUDA基线在新进程加载CUDA前设置NVIDIA_TF32_OVERRIDE=0，并禁用PyTorch TF32；ORT≥1.18另设use_tf32=0，旧版不传不支持的provider参数。读取本机选项确认支持的参数，且验证CUDA内存/算法配置未被自动回退。首片冷态之后预热1～4批大小，预热和编译耗时单列。25fps预算针对准备发布的后端，本轮自动候选结果按TensorRT计算；CUDA基线的性能结果照常记录。自动候选结果不改变当前产品默认后端，也不替代人工验收。
- 这是离线批量质量/容量测试。音频和完整特征提前可用，不证明V05在线首音、连续驱动、接收端或直播。
- 保存协议/语料SHA、每条音频SHA、后端/输出/阶段耗时、完整解码、采样长度和帧数。每条完成即写进度和结果；中断后不能把未执行条目当成功。

## 预设自动门槛

| 项目 | V04-Q1.2门槛 |
| --- | --- |
| 内容辅助核验 | 本地ASR转写；去标点/空格及大小写后CER≤0.15，且该条required_tokens不得缺失。数字等价仅使用每条预先登记的equivalences，不临时增加别名。否定词/品牌等仍需人工核查；ASR不能证明发音质量 |
| 媒体有效 | 每片含视频和音轨，完整FFmpeg解码，25fps，全部输入/输出指纹可追溯 |
| 末音完整 | 解码到与输入相同采样率的PCM，样本数不得少于输入；AAC尾部填充允许增加。长度门槛只排除确定截尾，仍需听感/波形/转写检查漏字与停顿 |
| 容器时长 | 音视频时长差绝对值≤80ms；音频样本完整性同时满足，不能用时长容差掩盖丢采样 |
| FP16数值筛查 | 相同帧序列的嘴周ROI（源68点的48～67点加12像素边界）；逐帧MAE的总体均值≤4/255、p95≤8/255，ROI有效覆盖≥95%。仅为回归筛查，不替代感知质量 |
| 热态处理容量 | 从输入完整WAV可用到最终编码文件完成，排除进程/模型初始化；每条分别列冷/热态。热态总体容量≥25fps且p95帧均处理耗时≤40ms，模型裸推理另列。达不到即实时预算未过，不按模型fps代替整链 |
| 资源 | 每后端采样本进程及子进程CPU/RSS，记录GPU整卡占用与可用的本进程显存。无GPU采样/峰值证据的字段保留未知，不能填0；长稳增长归V08，不以本次短测放行 |

## 必需人工检查

每条按正常速度完整观看/试听，再看嘴周：文本和末句完整、数字/品牌/中英读音正确；无错音色、身份改变、明显嘴周变形/接缝、持续闪烁或语音与口型明显错位。错词导致事实变化、否定词丢失、截句、串音色、人物身份变化为阻断缺陷；任一条出现即不放行。其他可见/可听缺陷须逐条登记并修复或形成明确发布限制，不能以平均分抵消。

自动ASR不通过时逐条区分ASR误识别与TTS读错；没有检查证据时保持待验。截图只证明选定帧，不代表全段动态检查。当前V03听感/浏览器实录仍待验，50条结果也不自动放行V03/V04整关。

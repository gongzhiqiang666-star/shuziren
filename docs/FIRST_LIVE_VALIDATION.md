# 下一步：完成第一条真实数字人播出链路

更新日期：2026-10-31。当前应用基线：`fa2d8c913398602f1768f2b2c54a3cbc7fd4a6f6`；软件与独立 CI 的既有证据见[交付状态](IMPLEMENTATION_STATUS.md)。本文是下一阶段执行顺序，本链路真实语音/口型模型、目标机器和淘宝验收项仍待完成；已有真实 BGE CPU 验证结果继续有效。

## 1. 本阶段只解决一个问题

用 **一个授权人物、一种授权声音、一个商品、一台目标电脑、一路输出**，证明新输入的话术能经过真实语音和口型模型，进入 OBS，并在获准的淘宝路径正常接收。

完成物是可复现的运行步骤、真实样片、资源/时延记录、故障与接管记录。已有商品、人格、记忆、审核、队列、成本和输出模块继续复用；模型测试发现的具体缺陷再进入开发。

### 固定第一条链路

本地工作台 → 已审核话术 → 本地 CosyVoice3 → 同一份 WAV → LiveTalking / MuseTalk → 独立输出页 → OBS → 获准的淘宝输出路径。DeepSeek 接入现有话术生成入口，不参与视频生成。

第一步先用现场新写、人工审核的句子排查媒体链路；出声和口型通过后，再验证 DeepSeek 新问题生成、事实核对和审批流程。人工路径通过不代表 DeepSeek 已验收。

| 方向 | 本阶段安排 | 进入下一步的条件 |
| --- | --- | --- |
| 高端真人路线 | 沿用现有 CosyVoice3 + LiveTalking / MuseTalk 接口，在一台 NVIDIA 目标机实测 | 模型真实加载，现场新句能播出，接管有效 |
| LivePortrait 动作增强 | 基线通过后做一个离线动作素材对照实验；先固定小幅动作和闭嘴源素材 | 相同 WAV、构图、编码下，动作改善且身份/嘴周/口型不恶化 |
| 低端真正 3D 路线 | 已提供独立 v0.3 验证页：GLB 资产、嘴形/眨眼控制、WAV/录音和轨道；在目标低配机检查观感与最终帧率 | 先证明人物和中文嘴形可接受，再开发与业务派发的整合；当前不是低端商用完成版，见[本地验证说明](AVATAR3D_LOCAL.md) |
| 其他已调研项目 | 暂存为备选，不加入此次链路 | 只有基线出现明确无法解决的问题，才针对该问题重开选型 |

LivePortrait 动作素材叠加口型仍属于视频人物路线，不能作为低端真正 3D 已完成的证据。低端路线也不能仅用卡通形象跑通就认定满足真实人物观感要求。

## 3. 按这五道关执行

| 顺序 | 实际操作 | 通过后留下什么 | 不通过时处理 |
| --- | --- | --- | --- |
| A：安装与加载 | 按[启动说明](LOCAL_SETUP.md)启动工作台和数据库，分别安装并加载真实 TTS/媒体服务，运行已有诊断 | 机器配置、代码/权重版本、诊断报告、模型加载结果 | 先修依赖、地址、驱动或素材；不以 HTTP 可达认定口型可用 |
| B：第一条真实样片 | 现场写 5–10 条新句，审核、真实合成、试听、通过独立输出送入 OBS；包含价格、规格、停顿 | OBS 原始录制、同源 WAV、任务编号和资源占用 | 按声音、嘴周融合、媒体传输分段定位；失败样片保留 |
| C：动态问答与质量 | 接入 DeepSeek 现场新问题；运行现有 50 句口型语料、传输校准、关闭管理页、接管/恢复和断线检查 | 逐例质量结果、分段时延、30 分钟记录、失败条件 | 发现问题只修对应路径；不同时更换多个模型 |
| D：持续运行与淘宝 | 在目标负载下做 8 小时稳定性；获准账号逐项确认实际画面、声音、评论与业务接口 | GPU/内存/队列/帧率记录、平台接收证据、异常与恢复记录 | 本地和平台分别判定；未获权限的项保留待验收 |
| E：首个客户试用 | 用实际样片、部署步骤和成本记录与一位目标商家验证使用意愿 | 商家认可的质量边界、可接受价格、支持工时和是否付费试用 | 若效果或总成本不被接受，先调整交付范围与部署方式 |

以上是推进顺序，不是保证工期。目标机器、素材、模型和账号到位后再给实机排期。淘宝权限确认从 A 阶段并行进行，不等完成全部开发才发现平台路径不可用。

### 现有工具直接复用

工作台在默认 Compose 端口启动后，在项目目录执行：

```sh
python3 scripts/doctor.py --models --media-url http://127.0.0.1:8010
```

LiveTalking 端口或运行主机不同则替换 `--media-url`；原生工作台另加 `--mode native --url http://127.0.0.1:8080`。诊断只检查就绪条件，不发起 DeepSeek 计费请求，也不合成或推流。报告写入被 Git 忽略的 `test-results/`。

50 句使用 [`fixtures/lip_sync_50.json`](../fixtures/lip_sync_50.json)。OBS 录制、同源 WAV、传输校准与故障测试按[本地测试手册](LOCAL_TEST_RUNBOOK.md)执行，不另造一套验收脚本。

## 4. 判定标准和记录口径

- **真实生成：**使用首次合成的新句证明动态能力，缓存命中与首次合成分开记录。现有 TTS 包装器收齐整句 WAV 后才返回，不能将上游流式首包延迟当作本系统首声延迟。
- **画面：**在实际直播观看尺寸及嘴周放大检查身份变化、接缝、嘴角、牙齿闪烁和停顿闭口。严重问题未解决的头像不进入试点。
- **同步与流畅：**25fps 最终输出、传输绝对偏差不超过 80ms 沿用既有初始目标，均待实测。传输校准不等于口型语义准确；重复帧不能证明流畅。
- **时延：**分别记录问题到草稿、人工审核耗时、审核后合成、派发到本地首声、平台端首声。不要把人工审核时间混入模型推理指标，也不要用模型单项速度代替整条链路。
- **连续运行：**先过 30 分钟，再进行 8 小时目标负载；记录崩溃、显存/内存峰值、队列是否持续增长、失败率和接管行为。未跑满不能填通过。
- **实际播出：**工作台 `sent` 只说明媒体服务接受 WAV；独立输出、OBS 和淘宝接收分别留证。暂停后平台已有缓存不能当作已撤回。
- **成本：**按实际 tokens、运行时长、电耗、设备折旧、必要平台费用及支持工时计算，另列一次性部署费。暂不把“每客户每月约 2,000 元”当作已验证成本或定价。

### 一次测试至少保留这些记录

| 记录 | 填写内容 |
| --- | --- |
| 环境 | 日期、机器、操作系统、驱动、应用/模型代码提交、权重版本及哈希 |
| 资产 | 人物/声音授权台账编号、素材哈希、TTS 引擎指纹、头像与渲染配置版本 |
| 任务 | 语料编号或现场新句编号、任务 ID、是否命中缓存、实际 WAV 哈希 |
| 结果 | OBS/平台样片位置、质量问题、各段时延、最终帧率、资源峰值、队列变化 |
| 结论 | 已通过、失败或未测；失败原因；下一次只改变哪一个变量 |

## 5. LivePortrait 对照实验的明确边界

只有 B、C 基线可用后才进行：A 组使用原始闭嘴视频；B 组使用离线生成的小幅动作视频，分别预处理为头像，顺序运行同一份测试 WAV。保持人物、口型引擎、脸部显示尺寸和编码一致。

比较动作自然度、身份保持、嘴周接缝、停顿、最终帧率和准备成本。先用已锁定版本和具备使用权限的模型制作一个形象。实际更换头像需按媒体服务配置停止、切换、重启；编辑工作台资产档案不会完成切换。

动作增强没有明确收益就保留基线。动作视频制作通过也不代表已经支持直播中任意动作切换、真正 3D、无 GPU 实时人物生成或商用素材授权。

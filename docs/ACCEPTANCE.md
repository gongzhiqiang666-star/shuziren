# 验收清单

本文是四期计划的发布与流程放行标准；每条均是要求，不是已通过声明。任务执行时按下列标准形成用例和记录。

## 四期统一验收规则

每项任务必须依次完成：定义输入/预期/阈值 → 开发 → 本机真实执行 → 检查产物与副作用 → 异常/取消/清理 → 受影响回归 → 保存证据 → 放行。任一必需用例失败、阈值未冻结或证据缺失，都不能标记通过并进入下一业务流程。

- 自动检查负责文件、返回值、时序、队列和资源；口型、听感、身份及真实页面另留人工检查结果。两者不能互相替代。
- 结果区分：恢复/导入测试、原商业原生链、自有重建源码、本地真实媒体、平台端到端、真实经营效果。每种只证明实际覆盖范围。
- 不得出现错商品/错音色、接管后旧任务回流、配置/项目损坏、跨店越权或错误经营动作。发现此类阻断缺陷必须修复并回归，不能用平均成功率掩盖。
- 本地通过仅限记录的硬件/软件/素材；其他平台、显卡、语言和输出路径分别测试。必需条件缺失不算通过，可选增强可有理由延期，但不能借此删除原功能。

| 音画同步 | 相同音频的可核对标记/帧位置，测起始偏移及30分钟/8小时漂移 | V05前确定方法及绝对偏移/漂移阈值；嘴型语义仍需人工检查 |
| 质量 | 固定语料/素材、正常观看与嘴周、身份/闪烁、读音/音色/截断 | V04及候选原型前固定检查表、缺陷等级和可接受标准 |
| 资源和恢复 | CPU/内存/显存/队列时序、错误到恢复时间、停止释放 | V05前固定采样窗口和资源/队列界限，长稳不得持续无界增长；故障用例固定恢复条件 |
| 经营效果 | 准备时间、修改/事实错误、误报/漏报、采用率、费用及退款窗口 | 每个G任务试点前固定商家基线、数据口径、目标/观察期及可比条件；未知不能补为0 |

上述尚未确定的数字是待完成的验收前置任务，不是默认宽松通过。执行者依据目标硬件/业务要求先形成有版本的指标表，再测试；测试后不得为使结果通过而事后调低门槛。合理变更须记原因、影响并按新标准重新验证。

V05时间与输出指标现冻结为[V05-T1](V05_TIMING_PROTOCOL.md)，覆盖首音/首帧、冷/热态、迟到、声画配对及采样量化。该协议是目标与方法，不表示接收端或整关已经通过。

## 第三期：候选方案 X01~X16

每方案先固定版本/资源/使用条件/阈值，隔离运行原型，再接真实队列/取消/接收端对比；完成采用/不采用/延期决策。前三步和回归通过才可正式采用；不采用可关闭可选评测，不能关闭未完成原功能。

| 新包v179 X16 | 先静态线索再实际运行，以同硬件/素材/任务对比启动、真实生成、持续驱动、取消/恢复和输出；只有可运行且条件相当的项才比较 |
| TTS/数字人模型 | 同硬件与匹配授权素材检查画质/音质、首音/首帧、最终帧率/显存/同步，在线新文本与接管后恢复 |
| GPU/worker优化 | 冷热态/实际provider/缓存、真实故障重启和资源释放；改前改后对照，收益可测且回归不倒退 |
| 互动框架/三维/新平台 | 核实播放与状态责任边界、角色/动作实际范围、真实连接和使用条件，不能把演示或面部动画当整系统 |

一期/二期因必需问题提前执行的结果可复用，第三期补缺口。新包更快或画面更好只对具体测量任务成立，不能据此整体替换架构。方案调整需决策记录：证据→差异/收益→兼容/资源代价→实现→复测→回退。

## 第四期：进阶款 G01~G10

本期分“功能正确”和“业务价值”两层，技术通过不能自动证明经营增长。

| 范围 | 功能正确怎么测 | 业务价值怎么验 |
| --- | --- | --- |
| 商品知识G01 | 导入并修改规格/活动/价格，各内容/直播/问答版本一致；未知/过期不编造；源报表抽查核对 | 事实错误、补录工作量及更新成本 |
| 准备包G02 | 真商品生成清单/顺序/FAQ/话术，修改后实际编排播出正确版本 | 与人工准备基线比时间、修改量、采用率和开播完整率 |
| 复盘G03 | 每数字/问题/建议追到商品/时段/原记录，下一场任务确实落实 | 可执行建议及实际采用、跨场变化与不确定性；不把相关当因果 |
| 运营副驾G04 | 先事件重放核对误报/漏报，再真场测缺货/过期/重复问答/无声等；接管优先 | 有效提醒、错误动作、人工处理时间；直播稳定性不下降 |
| 内容G05 | 商品事实与语言版本一致、实际媒体可用和真实发布；取消重试不重复 | 制作时间、返工率、有效发布及有数据的内容结果 |
| 店内选品G06 | 已知库存/成本/限制的样本可核对，推荐有依据，缺数据不造精确分 | 小范围试播，比较费用/履约/退款后的结果与库存；不只看销量/GMV |
| 导购售后G07 | 真问题/授权售后记录抽样查答案和分类，纠正进入下次内容 | 正确回答、重复工作、人工负担和延迟退款原因；错答不能靠少转人工掩盖 |
| 外部选品G08 | 来源/供应商/采购条件→真实样品→小规模试卖 | 实际成本、质量、履约与退款，不把热度或推荐当供应商验证 |
| 预算G09 | 费用/归因窗口可核对，限定对象/额度/时间，暂停及失败恢复可测 | 真实小实验净效果，识别自然流量/活动影响；无订单数据不报精确ROI |
| 多店/交付G10 | 跨店隔离、模板不串活动/账号，工作台事实到动作可追溯，安装/迁移/长稳 | 少量商家/有限品类持续采用、维护成本及约定价值目标达标 |

试点前记录人工基线和目标，在约定观察期计费用与退款；准备时间等例子不得作为已取得成绩。可比性/数据不足则结论为不确定或条件缺失，不宣称增长。第四期先只读/草稿，再确认执行，再限定规则自动化。

## 证据等级

1. 单元测试或Mock，只证明对应逻辑。
2. 本地模型与媒体集成，只证明目标电脑的链路。
3. 真实淘宝账号联调，证明指定账号和路径。
4. 客户试点，记录持续使用、真实成本和维护工时。

每次记录日期、环境、版本、输入、预期、实际、命令退出码与未验证项。

# yunchuang_v122 最小真实直播准入设计

## 目标

在继续扩展产品功能前，准备并执行一条能够证明项目可用性的最小真实链路：现场新句经过真实语音与数字人口型模型，输出到 OBS，并最终由获准的淘宝测试直播间收到音画。

本阶段只准备准入工具和运行材料，不补外围功能，也不把 Mock、HTTP 可达或本地预览误记为真实播出成功。

## 技术基线

核心媒体方案以本地 `yunchuang_v122` 原交付包及其已恢复调用链为基线：

- Windows 负责原生驱动、虚拟摄像头、音频设备、OBS/直播客户端和平台登录环境。
- NVIDIA CUDA 环境负责语音、口型和人物推理；分别保留常规 CUDA 11.8 与 RTX 50 系 CUDA 12.8 环境分支。
- 原版 `VideoStreamManager`、音频队列、虚拟摄像头、SRS 和 FFmpeg 约定作为媒体行为参照。
- 重建工作台继续负责商品事实、人工审核、任务状态、独立输出与验收记录，但不另造一套未验证的媒体运行时。
- 第一轮只采用一种已验证可加载的本地 TTS 和一种数字人口型引擎；其他引擎不影响准入结论。

这不是复制原包的账号、授权或闭源资产。模型权重、人物、声音、平台账号和必要许可必须由合法来源提供并单独登记。

## 固定验证链路

```text
人工现场新句
→ 审核并冻结文本
→ yunchuang_v122 对应本地 TTS 生成新 WAV
→ 同一 WAV 驱动数字人口型
→ 原版式窗口/虚拟摄像头或 SRS 输出
→ OBS 同时捕获画面与声音
→ OBS 本地录制
→ 获准的淘宝测试输出路径
→ 平台观看端确认音画
```

优先验证虚拟摄像头路径，因为它最贴近原版交付方式；若目标直播客户端明确只接受 RTMP/浏览器源，则保留同一上游 WAV 和人物运行时，只替换最后一个输出适配层，并在记录中注明。

## 准备包组成

### 1. 资产清单

生成不含秘密和大文件的清单，登记以下项目的存在性、来源、版本、SHA-256 和授权状态：

- 原版运行目录及两个 Python/CUDA 环境；
- FFmpeg、SRS、WebView2、Playwright Chromium；
- 32/64 位虚拟摄像头 DLL；
- TTS、ASR、口型、人物推理模型和辅助 ONNX 权重；
- 一份授权参考声音及准确转写；
- 一个授权人物素材及其预处理数据；
- OBS 配置和测试平台路径。

清单只记录路径标签和摘要，不提交模型、人物、声音、密钥、Cookie 或平台令牌。

### 2. Windows 准入诊断

提供只读 PowerShell 入口，检查：

- Windows 版本、CPU、内存、磁盘；
- NVIDIA GPU、驱动、显存和 `nvidia-smi`；
- CUDA 对应运行环境与 Python 导入；
- FFmpeg/ffprobe、SRS、WebView2 和 Chromium；
- 虚拟摄像头 DLL、注册表指向和管理员修复前置条件；
- 音频输出设备和 OBS 安装；
- 必需模型和素材清单；
- 工作台、TTS 和媒体服务端口占用及 HTTP 状态。

诊断必须区分 `pass`、`fail`、`unverified`。它不能自动宣称模型画质、音画同步、平台权限或长稳通过。

### 3. 配置模板

提供不含真实凭据的本机配置模板，固定：

- 原版运行目录、选用环境和 GPU 设备；
- TTS、人物和模型目录；
- 输入素材、输出分辨率和 25 FPS 基线；
- 音频设备、虚拟摄像头/SRS 输出模式；
- OBS 场景名与录制目录；
- 工作台、TTS、媒体服务地址；
- 淘宝测试仅记录是否已获准，不保存账号秘密。

启动脚本只读取显式配置，不自动下载模型、不静默切云服务、不修改平台账号。

### 4. 五道人工关卡

1. **安装关：**干净 Windows 能找到全部运行时、驱动、模型和素材。
2. **真实生成关：**首次输入的 5–10 句能生成可播放 WAV 和人物画面，保留 WAV 哈希。
3. **OBS 关：**OBS 录制同时包含声音与画面；分辨率、帧率和设备来源可核对。
4. **平台关：**获准淘宝测试房间的观看端实际收到音画；本地成功不替代此证据。
5. **稳定关：**先连续运行 30 分钟，再决定是否进入 8 小时测试；记录 GPU、内存、队列、FPS、错误和恢复。

任一关失败即停止后续开发，先定位该关。平台权限未到位时只能判定到 OBS 关，不能写成真实直播通过。

## 证据与隐私

每次执行创建一个时间戳目录，保存脱敏 JSON 报告、配置指纹、WAV 哈希、OBS 录制索引、人工观察、失败日志摘要和最终结论。真实素材、录制、Cookie、令牌与密钥留在受控本机，不进入 Git。

结论只有三种：

- `passed`：该关有对应真实证据；
- `failed`：已执行且结果不满足标准；
- `blocked`：缺硬件、资产、许可或账号，尚未执行。

## 错误处理

- 缺资产、驱动或权限时立即失败并指出具体项，不自动降级到测试替身。
- TTS 或人物运行时返回成功但没有新产物时判失败。
- OBS 只有画面或只有声音时判失败。
- 平台端没有证据时保持 `blocked/unverified`，不使用工作台 `sent` 状态替代。
- 报告不得输出密钥、Cookie、完整环境变量或上游响应正文。

## 测试策略

- 在 Mac/Linux 对清单解析、配置校验、脱敏和报告汇总进行自动化测试。
- 对 PowerShell 脚本做语法和纯函数测试；真实驱动、GPU、OBS 和设备检查必须在 Windows 执行。
- 使用现有 `scripts/doctor.py` 的安全输出约定，新增检查不改变它“不证明真实播出”的边界。
- 最终验收必须来自目标 Windows/NVIDIA 机器、真实模型、OBS 录制及获准平台观看端。

## 非目标

本阶段不实现更多平台、不补全部逆向函数、不优化多路并发、不购买硬件、不自动发布直播、不绕过平台风控，也不承诺无 NVIDIA 的拟真人实时效果。

## 完成定义

准备工作完成需同时满足：

1. Windows 执行者无需阅读源码即可按文档完成安装前检查；
2. 所有必需资产和外部权限都有明确 `present/missing/blocked` 状态；
3. 配置模板不含秘密且能被诊断工具校验；
4. 每道关卡都有明确操作、通过标准和证据位置；
5. Mac 侧自动化测试通过；
6. 尚未取得 Windows/NVIDIA 或平台条件的项目明确保持未验证。

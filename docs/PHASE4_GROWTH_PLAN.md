# 第四期：进阶款——数字人直播与运营工作台

更新：2026-11-10。状态：计划任务，未开始功能开发或商家效果验收。四期顺序为一期入门款、二期高级款、三期候选方案、四期进阶款；整体入口见 [开发路线](DEVELOPMENT_PLAN.md)。本期收录经营分析中从第三点“除了直播可以做什么”开始的全部方向、实施建议、数据基础和验证要求。

## 1. 定位与价值

以已有数字人直播为执行入口，建设商品知识、直播准备、运营副驾、内容生产、选品及复盘的经营闭环。近期定位是“数字人直播与运营工作台”：可靠讲解与互动、减少准备和复盘工作、把现有商品讲准确并合理安排。经营能力是新增产品方向，不替代 yunchuang 原功能重建。

先验证准备效率、事实准确和商家采用，再验证经营效果；不预设自动化必然提升利润。平台原生工具会覆盖部分通用经营功能，本项目聚焦与直播紧密相连、数据可追溯且在目标商家真实可用的工作流。

## 2. 完整方向与优先级

| 方向 | 解决的问题 | 开发定位 |
| --- | --- | --- |
| 商品知识中心 | 信息零散、规格/优惠错误、资料反复录入 | G01，最高优先 |
| 直播准备助手 | 开播前选商品、整理卖点/FAQ、排顺序耗时 | G02，最高优先 |
| 场次记录与复盘 | 不知道哪里需改，下场缺具体行动 | G03，最高优先 |
| 直播运营助手 | 补讲、切品、活动过期及直播异常处理 | G04，高优先 |
| 内容生产与分发 | 预告/短视频/直播/多语言反复制作 | G05，高优先 |
| 店内选品与排品 | 自有商品如何主推/组合/安排 | G06，高优先、依赖经营数据 |
| 售前问答与售后分析 | 重复问答和退货原因未反馈至内容 | G07，中期 |
| 外部选品与供应商辅助 | 找新商品、对比采购和履约条件 | G08，中后期 |
| 广告与预算优化 | 内容与投放费用缺少可核对分析 | G09，后期 |

优先级表示投入先后；所有方向均保留，所需数据、接口或商家条件不具备时记录条件缺失，不删除任务、不虚构结果。

## 3. 运营能力的具体成果

开播前输出“直播准备包”：商品清单及顺序、每品卖点/人群/FAQ和不能承诺的信息、开场/转场/收尾话术、缺失资料、预告与短视频需求。资料可编辑和审核，再转成现有编排任务。

直播中做运营副驾：基于重复尺寸问题补讲、过期活动停用、集中问答补充下一轮讲解、无声/积压/长期未切品提醒。最初先做建议和已验证规则动作，积累真实记录再增加自动调整。

直播后做证据型复盘：建议定位到商品、时间段、脚本版本和真实问题。例如适用场景问得多但话术未覆盖，就形成补资料、生成不同讲解版本、下场对比的任务。建议必须能检查、执行和验证，不只输出“加强互动”等泛泛结论。

## 4. 选品的两条路线

先做店内选品/排品：用自有商品、成本、库存、成交、退款和历史场次回答“下场讲哪些、为什么、如何组合”。因素包括受众/直播形式匹配、实际利润结构、退货损失、补货/发货能力、资料与展示充分性、历史曝光/点击/成交。数据缺失明确标未知，不造精确综合分。

后做外部选品：需真实需求、竞争、供应商、采购、物流和质量资料，按“发现候选→比较→样品/小规模试卖→复盘”推进。热度不等于适合商家，推荐供应商不等于验证质量，外部选品不直接变成自动采购。

## 5. 数据底座与早期准备

| 数据 | 后续用途 |
| --- | --- |
| 商品ID/SKU、规格、价格/活动、来源/更新时间 | 准确讲解、知识库、选品 |
| 成本、库存、补货/发货条件、数据覆盖期 | 排品和履约/利润分析 |
| 场次、商品讲解区间、脚本版本 | 排品/话术复盘 |
| 问题、回答、来源与人工纠正 | FAQ、导购、内容改进 |
| 播放、切品、打断、接管与故障事件 | 运营和稳定性分析 |
| 可获得的点击、订单、退款、费用 | 经营结果和选品，缺数据不推造 |
| 下一场采纳了什么改动及结果 | 验证建议是否有效 |

一期/二期可在原任务内预留稳定商品/场次/任务ID、版本和事件记录，作为现有系统可诊断性建设；这不提前实施第四期经营自动化，也不阻断首发。正式商品模型与经营分析在本期G01建设。

优先从商家导出报表、人工录入及自有事件记录接入；真实接口具备后再自动同步。区分直接记录的播报/互动、平台给出的点击/订单、系统推断的关联。某句之后出现订单不能直接认定该句带来成交，缺订单数据不能报精确归因；退款和费用滞后必须进入结果窗口。

## 6. 任务编号与执行规则

本期工作包G01~G10，每包4步，共40项，使用 `Gxx-yy`；同任务的店铺/品类/渠道用 `/对象名` 子记录。默认全部待验证，不改变原功能状态。组内按01→02→03→04执行，后一项依赖前一项通过；组间前置如下。失败先修复复测，条件缺失停留本关，不能通过建议文本替代实际工作流结果。

第三期所有候选须有可追溯采用/不采用/延期结论。非必需增强可延期；第四期必需运行路径必须已通过真实验证，不能依赖尚未具备条件的候选。经营功能每步同时验证事实/数据正确、实际流程、异常/权限/恢复、前期直播路径回归；按预先固定的客户基线与目标判断成效。

## G01 商品知识与经营数据底座

前置：第三期评测结论已登记，选定生产路径稳定。

| 编号 | 开发步骤 | 本机/业务验证内容 | 交付与放行条件 |
| --- | --- | --- | --- |
| G01-01 | 统一商品事实与版本 | 商品ID/SKU、规格、适用人群、成本/价格/活动及有效期、库存/来源/更新时间；区分已核对/未知/过期 | 同商品跨话术/直播/问答一致；过期和缺失信息不被补造 |
| G01-02 | 记录场次与内容事件 | 场次、商品讲解区间、脚本版本、问题/回答/人工纠正、切品/接管/故障和生成成本 | 可按场次/商品/任务追溯；重试去重，时间与版本对应 |
| G01-03 | 接入经营数据 | 先支持商家报表/人工录入，再按真实可用接口接点击、订单、退款、库存；记录数据口径/覆盖期 | 样本与来源核对一致；缺字段标未知，不把互动当成交 |
| G01-04 | 建立统一数据检验与恢复 | 校验币种/单位/时区、重复、冲突、迟到订单/退款、权限隔离与备份恢复 | 错误可定位；纠正后统计可重算；跨店数据不混用 |

G01-01 复用一期 `ProductStore` 的商品 ID、版本和话术快照。现有问答从商品标题和说明取信息，旧商品说明仍可作为原文读取。新增的规格、价格、活动和库存须带来源、核对状态和有效期，迁移时无结构化证据的字段记为未知。验收使用同一个商品先生成话术，再修改价格和有效期，逐一核对旧稿快照、当前直播和问答是否引用正确版本，并确认过期活动及未知库存不会进入生成内容。

接入点包括 `scripts/llm_tasks.py` 的异步话术生成、`scripts/console_llm.py` 的同步生成和 `scripts/console_comment_reply.py` 的直播问答。三处均应从同一商品版本读取有效事实。已有话术仍保留生成时的版本，选用或播报前检查涉及的时效事实，避免活动到期后继续播报。

在控制台商品表单展开「结构化商品事实」，填写以下格式并保存。有效期可使用北京时间偏移 `+08:00`。

```json
{
  "活动价": {
    "value": "人民币 100 元",
    "status": "verified",
    "source": "商家活动表",
    "expires_at": "2026-12-01T00:00:00+08:00"
  },
  "库存": {"status": "unknown"}
}
```

启用结构化事实后，生成提示使用其中已核对、有来源且未过期的条目。旧稿继续保留，过期后需要重新确认并保存才能选用。清空表单中的事实并保存会留下空事实集，生成时将视为暂无已核对事实。

## 7. 商家验证、产品里程碑与交付

| 顺序 | 试点重点 | 价值判定 |
| --- | --- | --- |
| G01~G03 | 商品事实、准备包、基础复盘 | 准备时间、修改量、建议采用率、事实错误及可执行性 |
| G04~G06 | 运营副驾、内容复用、店内排品 | 有效提醒/误报、工作量、净效果、库存与履约；数据不足明确不确定 |
| G07~G09 | 导购/售后闭环、外部选品、预算建议与受控执行 | 正确回答、样品/试卖、退款及费用、动作边界，不只看GMV |
| G10 | 多店/工作台与正式发布 | 隔离、稳定性、迁移、维护成本及真实商家持续采用 |

先选少量试点和有限品类，不将一个店结果推广到全部行业。先只读分析/生成草稿，再商家确认执行，最后才对限定范围开放规则执行。调价、上/下架、采购和预算等动作明确对象/时段/额度及人工暂停；权限不足不偷偷改用其他路径。

每次实验记录：任务ID、客户与数据范围、代码/模型/规则版本、输入/预期/阈值、真实命令和动作、产物/日志位置、数据口径、指标/误差、人工采用、故障/复测及结论。经营效果区分效率、转化、净收益及延迟退款；可比性不足不宣称因果增长。文字脱敏结论入Git，客户数据/凭据/素材不入Git。

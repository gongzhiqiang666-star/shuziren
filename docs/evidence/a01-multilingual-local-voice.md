# MED-008 马来语/越南语本地语音方案

验证日期：2026-11-14

## 最终主链选择

恢复的 `voice_infer_malai_local` 与 `voice_infer_vietnam_local` 是 8111/8112 外部 F5-TTS HTTP 服务客户端。本机、候选包和独立媒体目录均没有交付这两个服务，把它们作为产品默认底层会形成无法自包含的隐性依赖。

已有 OmniVoice 路径则具备本机模型、常驻复用、语言缓存和直播输出的真实证据。因此产品主链保留原版本名兼容配置，但路由如下：

- `malai_local` → OmniVoice，默认 `ms-MY`
- `vietnam_local` → OmniVoice，默认 `vi-VN`

原两个 F5 客户端源码和公开接口继续保留，用于合法旧部署或候选方案差分，不删除原功能入口。

## 已有真实证据复核

进度台账中的 A01-03 记录：

- RTX 3060 同一常驻 OmniVoice 进程分别生成马来语 4.48 秒、越南语 4.36 秒；产物均为 24 kHz 单声道 PCM16、非静音。
- 模型仅加载一次；相同请求命中各自语言缓存，摘要一致且语言间不串缓存。
- 越南语场次完成商品轮播、优先插播、手动接管、恢复和停播，发送 1780 帧，70 秒双轨回采完整解码。
- 马来语同流程发送 1782 帧，70 秒双轨回采完整解码。

本轮新增 `tests/test_multilingual_voice_routing.py` 2 项，确认两个兼容版本均选择 OmniVoice 并传入正确语言，同时 v1 等既有版本不改变提供者。完整恢复契约 128/128 通过。

## 状态边界

这些证据足以证明源码主链与真实 Windows GPU 媒体链，因此提升为“Windows 验证通过”，但不等于语言质量最终验收。仍需母语人员听评、数字/货币/商品名/中英夹杂语料、更多参考音、CPU 性能，以及确有旧客户依赖时对原 F5 服务做差分。

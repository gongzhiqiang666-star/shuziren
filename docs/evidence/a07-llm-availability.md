## 本轮修复

原 `test_llm_availability` 未要求底层客户端抛出请求异常。底层会把连接错误转换成非空的“LLM 调用失败”字符串，上层因字符串非空误报“服务正常”。现改为探针请求必须 `raise_on_failure=True`，HTTP、解析、超时和连接错误都进入明确失败分支。

同时统一地址门禁：远端必须 HTTPS，本机回环测试可使用 HTTP；拒绝 URL 中的账号、密码、查询参数和片段。错误响应会替换当前 API Key，避免诊断文本回显凭据。

# A06-01 Windows 音频设备全局编号

验证日期：2026-11-14。环境：当前 Windows 本机、随包 Python/PyAudio。

## 修复

PortAudio 的 `get_device_info_by_host_api_device_index` 返回设备信息中的全局 `index`。旧实现却把 host API 内的局部循环序号交给后续播放器，在多 host API 环境可能打开错误设备。现改为返回设备信息的全局编号；枚举期间单个设备消失或查询失败只记录该设备错误并继续扫描，其余设备不再全部丢失。PyAudio 实例在成功和异常路径均终止。

恢复契约使用全局编号 99/98/97 的构造设备验证映射，并验证中间设备查询失败后仍返回前后两个可用设备。

## Windows 实测

真实枚举得到 2 个输入和 5 个输出。输出全局编号分别为 2、3、4、5、6，覆盖系统默认映射、NVIDIA Monitor、VB-Audio CABLE Input、VB-Audio 16ch 和 Realtek 扬声器。

逐个使用返回编号，以 48 kHz、16-bit、双声道打开 PortAudio 输出流，写入 100 ms 静音，随后 `stop_stream`、`close` 并 `terminate`。五个设备均成功打开和释放，退出码为 0。

本轮没有物理拔插设备，也未制造其他程序的独占占用，因此热插拔、独占冲突、播放中设备消失仍为 A06-01 待验项。

## 指定设备与释放

`AudioPlayer` 保持原二进制的无参数构造签名，通过新增 `set_output_device(global_index)` 选择枚举出的设备；播放中拒绝切换。打开 PortAudio 流时显式传递 `output_device_index`。新增幂等 `close()`，依次停止线程/流并终止 PyAudio；关闭后的实例拒绝重新启动，析构仅作为兜底调用同一关闭路径。

Windows 实测选择 VB-Audio CABLE Input 全局编号 4，使用产品播放器的 FFmpeg 转换与 PyAudio 路径播放 100 ms 静音并关闭；随后新建第二个播放器再次打开同一设备并播放、关闭成功。两实例均报告关闭，退出码 0，证明显式关闭后设备可立即复用。恢复契约覆盖指定编号传入 `open`、非法编号类型、播放中切换拒绝及两次关闭只终止一次后端。

## 编辑器坏媒体门禁

碎片音频编辑器载入目录时不再只检查 `.wav` 扩展名，而是解析 WAV，要求 PCM、1～8 声道、1～4 字节位宽、8～192 kHz、至少一帧且不超过 4 小时。任一损坏条目会明确指出文件并拒绝整个目录，避免编辑到一半才失败。语音模型新生成的文件也先通过相同门禁，再替换现有音频。

预览仅接受当前已加载的 basename，重新验证媒体后才编码，并设置 64 MiB 上限。恢复契约覆盖伪 RIFF 拒绝、有效 PCM 载入/预览、未知条目拒绝、预览上限及有效新音频转换；完整恢复基线通过。真实 MP3 输入由前置 FFmpeg/切片入口继续在 A06-01/A06-02 验证，编辑器自身仍以配套 WAV/TXT 为标准输入。

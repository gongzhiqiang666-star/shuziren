# A07-02 用户配置与私密字段迁移

2026-11-14 审计恢复版 `main_config`，发现损坏的用户 YAML 会被当作空配置，下一次保存可能静默覆盖原凭据；固定 `.tmp` 文件也缺少 flush/fsync，并发或断电边界不可靠。私密字段清单还遗漏 `client_secret`、`ark_api_key`、`session_token` 等常见别名。

现改为：文件不存在才返回空配置；损坏、不可读或非字典根节点明确抛出脱敏错误，不链接可能包含原行内容的 YAML 异常；保存使用同目录唯一临时文件、flush、fsync 和 `os.replace`，失败清理临时文件并保留旧配置。私密识别扩展到常见精确名称和 `_api_key/_secret/_password/_passwd/_token/_cookie` 后缀，递归覆盖字典和列表。

四项专项验证通过：损坏配置不会被保存覆盖；替换故障保留旧文件且无临时残留；嵌套私密别名完整提取/清空；旧交付配置迁移时用户值优先、用户文件持久化后才清空交付目录中的密钥。完整恢复基线五关通过。该安全修正有意偏离原版“损坏即空配置”的缺陷行为，避免不可恢复的数据丢失和凭据泄漏。

后续 A07-02 继续核对 OEM/登录资源边界、旧资源迁移、插件清单和实际 Windows 权限/UAC 条件；真实旧 OEM 包和 UAC 仍需对应环境。

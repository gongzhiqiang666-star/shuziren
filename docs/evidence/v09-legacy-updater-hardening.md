# SYS-010 兼容更新入口加固

验证日期：2026-11-14

## 原入口风险

主应用 `start_app_update` 仍连接恢复自原程序的更新器。核对发现原行为使用明文 HTTP 获取元数据和包、直接 `extractall`，并按文件就地覆盖；攻击者可同时替换下载地址和哈希，恶意 ZIP 可越界写文件，中途失败会形成混合版本。

V09 已有的托管候选包升级/回退验证不能替代这个用户可见兼容入口，因此本轮直接加固旧入口：

- 更新检查和下载必须使用 HTTPS，本机 `127.0.0.1/localhost/::1` 测试服务例外。
- 每个版本必须提供 64 位十六进制 SHA-256，应用停止前完成元数据门禁，下载后解压前复核实际包哈希。
- ZIP 拒绝绝对路径、盘符、`.`/`..` 路径和符号链接，并继续要求存在 `_internal/` 内容。
- 文件先复制到同目录临时文件，哈希一致后 `os.replace`；保留被覆盖文件备份并登记新增文件。
- 任一文件失败时倒序删除新增文件、恢复被覆盖文件；用户配置继续不被更新包覆盖。

## 自动验证

`tests/test_update_integrity.py` 8 项通过：HTTPS/回环规则、本机更新服务的多版本解析与排序、更新元数据门禁、SHA-256 正常/缺失/错误、三类越界路径及符号链接拒绝、失败注入后的覆盖/新增文件回滚、成功提交与配置保留。

Windows 实机占用补验使用不共享删除的原生文件句柄锁住目标文件：更新明确失败，旧文件字节保持不变，`.update-new` 暂存文件被清理；释放句柄后同一更新成功。事务日志现在只在 `os.replace` 真正成功后登记已替换/新增文件，避免把尚未改变的占用文件误判为回滚失败。

## 有意兼容偏差与待验

原厂默认地址 `http://111.230.31.15:5155` 是不可信明文通道，现会明确拒绝。这是安全修复，不允许静默降级。发布前需在自有配置中提供 HTTPS 更新服务和每包 SHA-256；随后补验真实更新器窗口、物理断电及跨多个版本包的整场回滚。V09 新托管部署链的既有升级/回滚证据继续保留，但不冒充本入口的正式服务验收。

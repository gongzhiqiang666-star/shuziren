# A07-02 v122 旧资源迁移验证

日期：2026-11-14

## 完成范围

- v122 商品配置改为两阶段导入：先完整读取、规范化并校验全部商品、话术、角色、编号和扩展字段，再开始写入数据库。
- 商品名称、商品信息和话术沿用当前产品的长度及非空约束；旧角色仍兼容任意非空字符串，`assistant` 保留助播语义，其余值维持原有主讲回退行为。
- 数字字符串按实际数值检查商品编号唯一性，例如 `8` 与 `"08"` 不再等到写入第二条时才失败。
- 旧直播 JSON 必须是非链接普通文件且不超过 16 MiB；读取前后核对 SHA-256，避免迁移过程中源文件变化。
- 音色、形象和商品联合迁移继续在同安装目录的临时快照中执行，任一后置商品失败都不会发布已经导入的形象或半套数据库。

## 验证结果

`tests/test_console_package.py` 13/13 通过，新增覆盖：

1. 第二条商品的角色无效时，第一条不会写入已有目录。
2. `8`/`"08"` 重复编号在落库前拒绝，原目录保持不变。
3. 先真实导入一套准备好的形象，再让商品校验失败，最终安装目录不存在 `data`，证明联合迁移没有发布半套资源。
4. 既有音色、形象、选择状态、话术顺序、主讲/助播角色和多品轮播选择回归继续通过。

本项证明自有迁移工具的事务和输入边界。来自真实 `yunchuang_v122` 的更多历史项目变体、OEM 私有资源及跨机器媒体路径调整仍按样本条件继续登记，不以当前夹具冒充全部历史数据验证。

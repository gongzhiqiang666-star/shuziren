# A04-04 输出尺寸与旋转验证

日期：2026-11-14。范围为固定画布的等比适配、形象素材旋转元数据和随包媒体程序解析；物理虚拟摄像头接收与人工构图不在本次结果内。

## 实现与自动验证

- 录播和人脸人手虚拟摄像头共用等比覆盖、居中裁切，不再把源画面直接拉伸到目标宽高。
- 横转竖、竖转横、同尺寸零复制和非法画布 4 项专项通过；输出模式回归 3 项通过。
- 形象规范化改用随包 FFprobe/FFmpeg，不再依赖系统 PATH；帧率改用 `Fraction` 安全解析，不再使用 `eval`。旋转有效尺寸与异常帧率 2 项专项通过。

## 真实受控媒体

用随包 FFmpeg 生成 320×180、25 fps、1 秒 H.264 样片。第一次仅写 `rotate` 标签没有形成 display matrix，`get_video_info` 正确返回 rotation=0，该轮保留为失败尝试，不计通过。第二次使用 `-display_rotation 90` 形成真实 Display Matrix：FFprobe 与产品解析均得到 rotation=90、有效尺寸 180×320、竖屏。

该旋转样片以 480p 规范化后得到 480×854、25 fps、rotation=0 的竖屏 H.264，完整解码通过；无旋转横屏样片得到保持 16:9 的偶数尺寸 852×480，完整解码通过。恢复基线五关通过。受控媒体位于忽略目录 `temp/a04-rotation`，不提交仓库。

五档输出另用 90×160、25 fps、3 帧受控 H.264 逐档走产品规范化入口，FFprobe 与完整解码结果为：480p=480×854、720p=720×1280、1080p=1080×1920、2K=1440×2560、4K=2160×3840；五档均为 25/1 fps，FFmpeg `-xerror` 解码退出 0。媒体位于忽略目录 `temp/a04-resolutions`。

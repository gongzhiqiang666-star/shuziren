# G10-01 本地账号认证

日期：2026-11-14

## 实现

- 新增共享 `accounts.sqlite3`：账号密码使用 PBKDF2-SHA256、32字节独立随机盐和600,000轮派生，只保存摘要；账号按店铺绑定 viewer/operator/admin 角色。
- 发行入口先用 `account-set` 交互式读取两次密码，不把密码放入命令行、日志或输出；`run --shop-id <店铺> --require-login` 才开启登录保护，既有单机启动保持兼容。
- 启用后，未登录 API 返回401；登录成功签发内存会话及 HttpOnly、SameSite=Strict Cookie，8小时到期，服务重启失效。注销立即撤销；改密码、改角色或禁用账号也会通过凭据版本使已有会话在下一请求失效。
- 角色不再由浏览器上报。每次写操作使用服务端会话中从账号库取得的店铺角色，并继续写入原权限审计；登录失败统一返回同一错误，不泄漏账号是否存在。

## 验证

- 账号存储专项3项：摘要/盐/轮次、跨店拒绝、改密、禁用、输入门禁和统一失败语义通过。
- HTTP认证专项：错误密码、正确登录、未登录401、viewer拒写、注销撤销、禁用后旧会话立即失效及审计通过；既有三角色与跨源令牌回归通过。
- 发行专项23/23通过，确认 `--require-login` 必须配合店铺，且安装版只使用安装根共享账号库。
- 真实 Chrome 完成错误密码、正确登录、身份显示、刷新保持、注销回登录页及注销后API 401；证据 `logs/validation/g10-login-ui-02/result.json` 和两张本机截图。报告不包含密码或会话令牌。

## 边界

该能力完成本机密码认证和按店角色绑定，不等于企业 SSO、远程身份提供商、找回密码或公网暴露。控制台仍只监听 `127.0.0.1`；生产多店、SSO和集中身份生命周期按试点条件继续验收。

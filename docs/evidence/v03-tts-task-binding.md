# V03-03b TTS任务绑定、取消与迟到隔离

2026-11-10，实现scripts/tts_tasks.py。父进程唯一决定任务结果是否可用，子进程只负责模型合成。一个管理器同时只允许一个任务，正常完成后保留相同进程/模型；取消终止本实例工作进程并等待回收，下次明确重新加载，不伪称取消后仍可零成本热启动。

派发前必须选用当前商品版本的话术及当前音色；保存商品版本、话术ID、音色ID和参考音/文字SHA256。完成时再次校验商品/选用稿/音色，检查输出位于自有tts目录、音色ID及音频哈希一致，变化则不接受音频。查询已成功任务时还会复查输入，后续改版/换稿/替换参考也会移除当前result并保留previous_result供诊断，不能继续作为当前可用音频。

任务状态保存在tts-task.json，重启将running记为interrupted而非自动重跑。180秒期限到时终止工作进程，失败后重试会重新建进程，避免旧协议响应混入新请求。所有临时/缓存/WAV仍在自有数据目录；取消或拒绝结果不等于所有生成文件已删除，未接受文件不可作为播放结果，磁盘回收策略留V03-04。

## 真实GPU验证

执行validate_tts_tasks，使用已有真实人声参考的隔离副本、新测试商品/两条人工话术。首次运行及加入完成后失效保护后的最终运行均通过。最终报告位于logs/validation/v03-task-binding-final/run-f8e5e92d5a3940d3a3df65515e8088eb/result.json，过程执行命令退出0。

1. 第一条真实合成成功；切换同商品当前选用稿后第二条成功，进程PID一致、model_loaded=false、model_load_count=1。
2. 再派发后重复派发被拒绝；0.1秒后取消，任务cancelled且无result，原子进程退出。
3. 取消后重新派发，新的PID真实合成成功，验证冷重启恢复。
4. 合成期间编辑商品，迟到结果failed且无result；最后关闭管理器，所持进程已退出。
5. 两个正常成功文件又经真实FFmpeg完整解码，均退出0。报告记录完整解码通过，不把被拒绝文件当成功结果。

另4项数据/状态测试通过：完成后商品变化、选用稿变化、参考文字变化均失效；未选用稿不能启动worker。此处使用指纹状态夹具，不是声学验证。既有1项真实子进程协议测试回归通过。

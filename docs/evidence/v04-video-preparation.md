# V04-02b：自有视频制作与人脸预处理

## 交付与兼容边界

新增`avatar_prepare_worker.py`和`AvatarTasks`，接入控制台“从视频制作新形象”。制作在自有任务目录规范化视频、提取帧、调用恢复版SCRFD/PFLD预处理，再由父进程验证输入指纹并导入自有形象库；保留规范化视频和形象信息，不在原视频旁写输出。制作中页面刷新只恢复任务，支持状态、取消、错误及退出回收。新形象不自动改变当前选择，完成后由形象列表选择使用。

当前适配器支持1～240秒、输入不超过2GiB，25fps形象不超过6000帧、自有素材不超过1GiB；超限明确拒绝，不截断冒充完整导入。清晰度入口保留480p/720p/1080p/2K/4K，但本次实机仅证明720p单人视频，其他档位、非25fps/旋转/横屏、复杂侧脸和多人仍需后续场景验证。音画驱动、遮挡、KT板等原能力未删除。

制作使用独立进程，正常完成/失败/取消均清理本次prepared临时目录，任务日志保留。父进程才有导入权：结果目录或源指纹不符时拒绝；取消后的迟到结果不导入。600秒工作进程上限、FFmpeg规范化300秒、探测30秒。启动前持久化失败不启动工作进程；重开将未完任务标为中断，不凭记录中的PID结束任何进程。正常取消仅针对本实例Popen及捕获到的子进程，等待子进程终止后清理文件。psutil已在现有核心依赖清单中。

## 本次实际发现并修复

1. 关键点模型构造原先没有显式provider，在本机ORT构建下加载失败，且错误被“load onnx failed”覆盖。改为按CPU/CUDA明确创建session，保留原始错误；路径解析器中未使用过的`pfld`拼写同时纠正为实际`pfpld`文件名。先前对“加载失败仅由文件名导致”的初步判断不准确，以本记录为准。
2. FaceDetect原来只有文件输入转RGB，数组输入直传；实机原生对照证明两种输入应保持相同颜色转换。
3. 恢复版遗漏裁脸上下文：用原生函数的输入跟踪定位左右约10%、下方约10%扩边，以及比例统计/最终记录两遍的右端列差异。补上扩边、整数坐标和原始偏移；三帧最终框与68点坐标均与原生完全一致。边缘裁切/其他人物仍不能由这三帧推定通过。
4. 保留可选视频/元数据时，文件循环变量曾覆盖用户形象名。已修复并增加测试。修复前实验原报告保留`result.original.json`，`result.json`纠正为失败；不拿当时漏检的绿色结果作为最终通过证据。
5. Windows终止进程树返回时子进程可能仍在退出，补充等待实际子进程结束再清理。最新真实FFmpeg子进程被观察后再取消，工作进程/子进程均退出，耗时约0.281秒；坏媒体返回可理解错误而非整条底层命令。

# 第二期：高级款开发任务清单

更新：2026-11-10。主路线见 [最终执行计划](DEVELOPMENT_PLAN.md)，验证记录见 [本机逐关验证](LOCAL_VALIDATION.md)。本清单将 A01~A07 拆为可执行任务；原工作包编号保持不变。

## 编号和放行规则

- `Axx-yy`：高级款工作包内的执行步骤。每组按编号顺序推进；表中第一项依赖该组前置条件，其后每项依赖上一项通过。
- 同一步有多个引擎、平台、语言或输出时，创建 `Axx-yy/对象名` 子记录，按清单逐个开发和本机验证；所有必需对象通过，父任务才通过。
- 当前所有任务均为待验证，表格不声明已完成。开始时登记负责人/源码版本/环境/输入/预先冻结的指标/命令，结束时记录真实结果、产物、异常、回归及放行结论。
- 失败或条件缺失先处理当前任务，不进入后续业务流程。候选增强允许得出“不采用”，原功能不能因此删掉；与入门款相同的已验证路径补剩余分支即可。
- 每步必须完成真实功能验证、关键异常/停止清理，以及本次影响的已通过路径回归。最终发布门槛含真实平台、8小时长稳和干净安装；导入或Mock不放行。

## A01 多引擎、多语言与主播/助播

前置：V09 通过。步骤顺序如下。

A01-01 的一期语音基线来自 `scripts/tts_worker.py`、`scripts/tts_tasks.py` 和 `scripts/tts_cache.py`。任务请求传入音色 ID、文本、语速、语言及缓存选项，返回由工作目录持有的 WAV、摘要、时长、采样率及提供者信息。缓存键绑定引擎指纹、参考音和参考文本摘要、合成文本、语速与语言。新引擎接入时逐项核对请求字段、输出所有权、参考音切换、取消和进程释放，保留已有 IndexTTS 行为。ZipVoice 与 OmniVoice 的真实模型运行仍列在 A01-02。

驱动基线见 `scripts/live_avatar_client.py` 和 `scripts/live_frame_channel.py`。请求和结果绑定场次、任务、PCM 摘要与采样时间轴。实时帧按场次连续编号，接收端检查尺寸、帧序和归属。文件输出另校验路径与摘要。适配器应在关闭后拒绝迟到结果并释放进程和帧通道，换引擎时复测错场次、错帧序、取消与重开。

### A01-02 本机复验入口

从仓库根目录执行。构建目标需是新的目录，`$reference` 为已有的授权运行资源，`$voiceData` 为带已选参考音的验证数据目录。

```powershell
python -m scripts.stage_media_runtime --reference $reference --destination $runtime --include-zipvoice --include-omnivoice
& "$runtime/_internal/env/python.exe" -X utf8 -m scripts.validate_tts_tasks --runtime-root $runtime --source-data $voiceData --report-directory $reports --engine omnivoice --model-root $omniModels
& "$runtime/_internal/env/python.exe" -X utf8 -m scripts.validate_tts_tasks --runtime-root $runtime --source-data $voiceData --report-directory $reports --engine zipvoice --model-root $zipModels
```

OmniVoice 模型目录提供主模型、配置及 `audio_tokenizer`。ZipVoice 模型根目录提供 `zipvoice_distill` 和 `vocos-mel-24khz`。控制台启动时通过 `--tts-engine` 和 `--tts-model-root` 指定同一引擎及外置模型目录，并在配置中选定相应的媒体运行资源。任务验证报告包含模型复用、取消与恢复、过期结果拒收、进程关闭和完整解码。人工听感与直播输出按各自用例登记。

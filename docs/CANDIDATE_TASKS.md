# 第三期：候选方案逐步评测任务

更新：2026-11-10。对应 [整体计划](DEVELOPMENT_PLAN.md) X01~X16；高级主线见 [高级款任务](ADVANCED_TASKS.md)。本清单是工程评测任务，不宣称新候选已完成部署或再次核验所有上游版本。

四期顺序：入门款→高级款→候选方案→进阶款。完整可选评测集中在第三期；下文较早的V/A插入点表示解决前两期必需功能阻断时允许前置的最小验证，而非要求提前执行全部增强。第三期复用这些证据，逐对象形成采用/不采用/延期结论；条件缺失不记通过。第四期见 [进阶款计划](PHASE4_GROWTH_PLAN.md)。

## 统一编号、顺序与决策规则

每个 `Xxx` 固定四步：`-01` 条件与基线 → `-02` 隔离原型 → `-03` 真实链路对照 → `-04` 决策与回归放行。`-02`依赖`-01`通过，`-03`依赖`-02`通过，正式采用依赖前三步及决策通过。`-03`只在隔离适配/测试配置执行，不在决策前替换生产默认路径。

- 未触发任务保持待验证并记录触发条件，不为凑进度强行评测。原生算力证据可以复用但不得直接标重建适配通过。
- 任务运行结果：待验证/通过/失败/条件缺失。`-04`另记录采用/不采用/延期及理由；“不采用”不是模型测试通过，也不是原功能完成。
- 条件满足但原型失败：先修复复测；如果技术/成本不合适，可直接形成`-04`不采用结论，明确哪些步骤未通过，不伪造`-03`。可选方案关闭后继续稳定主线；必需能力仍缺失时主线不能放行。
- 未具备硬件/账号等条件：当前任务保持条件缺失。可选方案经明确记录延期后回到稳定主线；不可将其写为通过，必需功能不能以延期绕开。
- 每个引擎变体、框架、平台、语言或显卡都使用 `Xxx-yy/对象名` 子记录，各自有版本/条件/结果；不以一个对象通过宣告整组通过。
- 阈值必须在运行前冻结；固定源码/模型/授权输入/设备/输出比较，记录冷/热态、真实最终帧率、首音/首帧、同步、质量、资源、取消和失败恢复。自动断言与人工质量结果分开。

## 插入主线的执行顺序

| 主线位置 | 候选执行顺序 | 返回条件 |
| --- | --- | --- |
| V00起/第三期参考基线 | X15固定现有版本并逐V关核验；第三期先X16运行参考包，再比较新候选 | 现有方案真实证据明确，不能只评测新模型；X15必需缺口不绕过 |
| V00/V03/V04 | X01基线 → X02常驻；语音不达标触发X04，画质/维护不足触发X03 | 所需能力在选定路径真实通过，再进入下一V关 |
| V05 | X02队列接入 → 若响应不足X05 → 若媒体瓶颈X08对应子项 | 持续新语音/同步/取消达到V05门槛 |
| A01后 | 未触发的X03/X04按需求决策 → X06 → X07 | 完成决定或明确可选延期；不延误原功能缺陷修复 |
| A04后 | X08其他优化 → 有远程需求时X09 | 所选增强回归通过，默认路径稳定 |
| A03及A06相关任务后 | X11录播/手持 → A02及A05完成后X12新增接入 | 每个子对象独立放行，不替代原模式和平台 |
| A07后 | X10三维 → X14容量/硬件；X13仅按研究需求进入 | 独立扩展验收，不改变高级原功能验收标准 |

X编号为分类顺序，并非要求X01一直执行到X16；实际前置条件如下。没有触发的增强不是主线阻断项。

## 3. 已处理的联调问题

- LiveTalking 当前会话 ID 为字符串，前后端与媒体协议统一，拒绝数值 ID 的错误响应。
- 本地结束与接管均返回媒体停止结果；停止失败必须显示手动处理提示。
- 数据库里的旧媒体 ID 不代表浏览器还连着；派发按钮要求当前场次实际 WebRTC connected。
- 同一场次的数据轮询不会关闭已有 Peer；离开工作台后需要重新连接。
- 上游明确返回会话已不存在时可安全重连；未知停止失败不能被忽略。
- 数据库确认丢失时保留已生成 WAV，避免提交为 ready 后误删唯一音频。
- 已开始的发送若超时、失败或遇到接管，结果按不确定处理，禁止自动重播。
- 修复实际审计命中的前端与 Python HTTP 测试依赖，并重新构建 / 测试。
- 首次 GitHub 检查发现服务容器健康命令的单引号解析问题；改为受支持的双引号后，整套测试和实际容器启动均通过。

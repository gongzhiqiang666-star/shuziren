# 本机逐关开发与验证

日期：2026-11-10。适用：基础款全部开发及高级款后续批次。整体范围见 [开发路线](DEVELOPMENT_PLAN.md)。

## 1. 必须遵守的开发循环

1. 先定义本流程的输入、预期结果、失败行为、测试素材和通过阈值，再开发实现。
2. 在本机运行新源码，通过真实文件、模型、设备或界面完成当前流程；检查实际产物和副作用。
3. 验证正常输入、关键边界、失败恢复与停止清理；回归本次变更影响的已通过流程。
4. 记录命令、版本、退出码、实际结果、日志/样片/截图及剩余问题。自动化能验证的行为由脚本断言；画质、听感和真实界面记录人工检查结果，不冒充自动判定。
5. 所有本关必需用例通过且证据完整，才能放行下一流程。失败则修复、复测，不能只记 TODO 后继续。

缺资源或账号时本关保持未通过，仅开展本关诊断与补齐工作，不进入下一业务流程开发。已通过流程在代码、模型、驱动或配置发生相关变化后需要重新验证。修复局部问题时先跑针对性检查，再跑受影响回归，避免无变化重复全量压测。

流程放行结果使用“待验证/通过/失败/条件缺失”记录，与 FUNCTION_MATRIX.md 的六种功能状态分别管理。本机单流程通过不能把一个包含多分支的原功能整体标为端到端通过；真实 GPU/驱动/平台能力必须有对应环境证据。Mock 仅用于逻辑回归，不作为真实功能放行依据。

## 3. 高级款逐关方式

基础款 V09 通过后，按 A01→A02→A03→A04→A05→A06→A07 推进，每包再拆成单引擎、单平台、单模式或单工具的流程。每个子流程遵循第 1 节循环，通过后才做下一个。任务重合时补齐原能力剩余分支，不重复搭建基础实现。

- 新语音/数字人引擎：固定输入、版本与硬件，对比画质/音质、首帧/首音、最终输出、显存、取消与释放；基础默认路径回归通过。
- 新平台：分别验证登录、商品、评论、控制、断线恢复和实际输出，不能拿淘宝通过结果代替其他平台。
- 脸手/录播/报时：真实素材，验证切换、原音轨与插播、打断及恢复，不能只导入模块。
- 字幕/贴片/IP/云端生成：创建项目到实际产物/发布结果，检查失败、取消、保存重开与旧数据兼容。
- GPU/worker 优化：同条件改前改后对照；功能、画质和同步不倒退，收益可测，故障可回退；再做相关长稳测试。

本机不能覆盖的硬件、语言、平台或多路容量保留明确待验证项；本机通过只证明已记录的配置与输入范围。

## 4. 记录模板

每次记录：关卡/用例、功能 ID 与分支、日期、源码提交及未提交改动、环境/驱动/模型版本、输入及预期、真实执行命令、退出码、结果、产物位置、测量指标、缺陷及复测、是否放行。只有必要且脱敏的文字结论进仓库；日志放 logs/validation/，人物/声音/平台录制等放被忽略的本地数据目录，不提交素材与凭据。

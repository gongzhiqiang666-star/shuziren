# 低端 3D 本地验证版 v0.3

本版的目标是让你立即在本机观察真正的三维人物、实际音频驱动的嘴形和最终播放效果。它复用现有项目，并增加独立的 `/avatar3d` 页面；原有高端真人视频工作台继续保留。

如果让本地 Codex 帮你安装和启动，使用 [CODEX_LOCAL_DEPLOY.md](CODEX_LOCAL_DEPLOY.md)。其中提供可直接复制的任务说明、Mac/Windows 分步命令、生产构建与启动、常见问题和实际验收报告格式。

## 最快开始：使用已构建的验证包

1. 解压 `shuziren-avatar3d-v0.3-preview.zip`，保留 `app` 文件夹和启动文件的相对位置。
2. 电脑需要 Node.js，建议使用 Node.js 24；在终端执行 `node --version` 可以检查。预构建包无需 npm 安装、Docker、PostgreSQL、CUDA 或模型服务。
3. 在解压目录打开终端，执行：

```sh
node start.mjs --dir app
```

4. 打开 **http://127.0.0.1:5173/avatar3d**。服务仅监听本机；按 `Ctrl+C` 停止。端口被占用时加 `--port 5174`，然后打开对应地址。

Windows 也可双击 `start-windows.cmd`。macOS 可在终端执行上面的 Node 命令；`start-mac.command` 提供同样入口。若系统阻止执行脚本，不需要更改全局执行策略，使用终端命令即可。

建议先用桌面 Chrome 或 Edge 验证；Safari/Windows/OBS 原生环境的实际验证状态以交付记录为准。此版不要求 NVIDIA/CUDA，但三维显示仍使用 WebGL 图形能力；电脑和浏览器的图形加速情况会影响速度。

## 第一次验证只做这六件事

1. **看人物。** 页面会加载内置 CC0 人物。拖动鼠标旋转、滚轮缩放，确认是实际三维网格。示例人物用于验证，不代表最终客户形象或真人感验收通过。
2. **试嘴形。** 点击“闭唇、唇齿、张口、圆唇、静止”等按钮，检查嘴唇、牙齿和下颌是否合理。
3. **提供声音。** 点击“导入 WAV”，或“录一段声音”。录音最长 60 秒，WAV 最长 5 分钟、32 MiB；文件只在当前浏览器处理。录音须由用户点击并授予麦克风权限。
4. **播放口型。** 本机完成音频分析后点击播放；试暂停、拖动进度和重播。可调嘴部幅度及嘴形时间偏移，观察同一音频下的变化。
5. **保存样片。** 点击“录制人物与声音”，从音频开头录制，最长 3 分钟；结束后下载视频。浏览器不支持所需录制接口时，页面明确提示改用 OBS。
6. **导出记录。** 导出验证记录、WAV 或口型轨道。记录包括模型能力、音频哈希、嘴形模式、画面尺寸和当前帧率，不会自动给真人感或中文嘴形打合格分。

推荐现场测试句：

> 这款保温杯容量五百毫升。今天的测试价格是一百二十八元。请先看清规格，再决定是否购买。

再单独说“爸爸、妈妈、杯子、服务、五百、保温”，并加入停顿。这些只是检查语句，不是识别准确率测试集；完整口型验收仍使用仓库已有的 50 句语料。

## 两种口型来源要分清

### 自动口型：可立即运行的声学试验

默认先在本地 Web Worker 分析整段实际音频，再用音频播放器的 `currentTime` 驱动嘴形。不会根据文字长度估时，不会重新生成另一份声音，也不是仅按音量控制张嘴大小。

分析器采用固定版本 HeadAudio 的 MFCC 声学分类与 15 种嘴形。随包模型为上游 `model-en-mixed.bin`，训练来源是英语；上游也明确列出预测与静音检测局限。**中文精细口型尚未验收，不能把“已生成轨道”理解为每个字嘴形正确。** 本版先让你观察实际结果，决定是否继续投入中文专用对齐和形象调校。

默认播放已有整句音频，因此没有把分析耗时隐藏成实时推理性能。分析在后台线程执行；更换音频会终止旧分析。分析失败会明确报错，不会静默换成音量开合模式。

### 导入轨道：验证独立对齐的结果

支持 Rhubarb 原生 JSON，以及本项目标准格式。Rhubarb 文件没有音频哈希，只能验证时长，页面会标记“仅时长匹配”。标准格式如下，所有时间单位为秒：

```json
{
  "version": 1,
  "duration": 1.2,
  "source_audio_sha256": "此处填写原始WAV文件字节的64位小写SHA256",
  "cues": [
    { "start": 0, "end": 0.2, "viseme": "sil" },
    { "start": 0.2, "end": 0.35, "viseme": "PP" },
    { "start": 0.35, "end": 0.9, "viseme": "aa" },
    { "start": 0.9, "end": 1.2, "viseme": "sil" }
  ]
}
```

上面是格式示意，不是任何真实音频的可用轨道。支持 `sil / PP / FF / TH / DD / kk / CH / SS / nn / RR / aa / E / ih / oh / ou`；轨道最多 2 MiB、30,000 段，时长与当前音频容差 20ms。错误哈希、未知字段、重叠、倒序和越界时间会被拒绝。校验一致只证明绑定关系，不证明发音正确。

## 与已有工作台配合

完整工作台启动后，在“审核与播报”中合成并试听真实语音，点击“下载 WAV · 用于 3D 验证”，再导入 `/avatar3d`。工作台右上角有“3D 验证室”入口。

这个版本提供的是显式导出/导入路径，尚未把 3D 渲染器接入业务自动派发、场次接管和淘宝开播。试验页里的录音、手动嘴形和音频播放不经过商品事实审核，应仅用于本地质量测试。原 LiveTalking/MuseTalk 的审核与派发路径保留。

## OBS 采集方式

本版提供“纯画面 / OBS”模式：隐藏操作面板，用 OBS 窗口采集当前浏览器，并按操作系统配置音频采集。按 Esc 恢复操作面板。绿幕背景可以用于后续合成。

此模式需保持当前浏览器页面打开；它不是原高端路线的独立 WebRTC 输出链接。不要把试验页 URL 当成自动加载用户文件的独立 OBS 浏览器源：其他浏览器进程没有当前页面选择的模型和音频。

## 从 GitHub 源码启动

检出 `codex/low-end-3d-preview` 分支后，在项目根目录执行：

```sh
sh scripts/start-avatar3d.sh
```

Windows PowerShell：

```powershell
powershell -File scripts/start-avatar3d.ps1
```

源码启动需要 Node/npm 和 Python 3.10+。脚本下载并核验一次 CC0 样例，执行 `npm ci`，启动本机 Vite。`--no-sample` 跳过样例下载，随后在页面选择自己的 GLB；`--prepare-only` 只准备资源和依赖。准确的资产来源、授权与哈希见 `docs/AVATAR3D_ASSETS.md`。

自己导入的模型须是自包含、单场景 GLB，≤80 MiB，并有可用 Oculus 或 ARKit 嘴形。当前不加载外部纹理、Draco/Meshopt 压缩资源、VRM 扩展专用表情或任意 FBX；这些支持不包含在首版范围。

## 当前验证边界

- 自动化测试核对轨道校验、播放器时间轴、真实浏览器渲染、音频分析和录制链路。
- 浏览器测试的合成测试音只用于验证数据和播放路径，不能证明中文声音或嘴形效果。
- 当前示例的材质、头发、姿态与通用嘴形是起点，尚未通过客户真人感验收。
- 目标低配机上的稳定帧率、中文精细嘴形、Windows/macOS/Safari、OBS 原生采集、淘宝实播、8 小时负载继续分别验收。
- 此版没有新增付费 AI API。导入音频和录音只用于质量检查；本地 CosyVoice 的目标硬件性能仍需独立测量。

把导出的验证记录和一段正常观看尺寸的样片一起保留，后续根据具体问题调模型、材质、嘴形或性能。
